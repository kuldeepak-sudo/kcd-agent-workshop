Technical setup

Token exchange, without an Enterprise licence

This demo is a port of Tyk's own tyk-demo repo's mcp-token-exchange deployment. The original uses Tyk's built-in Enterprise "OAuth 2.0 Token Exchange" middleware — a hard licence requirement. This port keeps the identical outcome (a narrowed, identity-preserving token) but gets there with a custom Tyk OSS gRPC plugin instead, so the whole workshop stays genuinely open source.

ℹ️
Everything below was built and verified against a real Tyk OSS Gateway (v5.13.2) in a kind cluster — not written from docs alone.

The plugin, concretely

A small Python gRPC service (services/token-exchange-plugin) implements Tyk's Dispatcher coprocess service and runs as a postPlugins hook on the acme-mcp-proxy API — the last step before Tyk proxies a request upstream, after its own native JWT auth has already run.

# tyk/acme-mcp-proxy.oas.json — the relevant slice
"middleware": {
  "global": {
    "pluginConfig": { "driver": "grpc" },
    "postPlugins": [{ "enabled": true, "functionName": "TokenExchangePostHook" }]
  }
}

On each tools/call, the plugin:

  • Reads the (already-verified) inbound JWT's sub and entitlements claim — no need to re-verify the signature, Tyk's own JWT auth already did.
  • Looks at the JSON-RPC body to see which tool is being called, and maps it to the one scope that tool needs (customers:read, customers:write, or refunds:write).
  • Not entitled? Sets request.return_overrides — a 403 with an insufficient_scope body, short-circuiting before anything reaches the MCP server.
  • Entitled? Mints a new RS256 JWT — sub preserved, aud=api.acme.internal, azp=tyk-mcp-gateway, scope= the one narrowed value, 60s expiry — and rewrites the outbound Authorization header via request.set_headers.

The plugin also serves its own JWKS (/.well-known/jwks.json) so the downstream acme-api route — and acme-resource-api itself — can independently verify the exchanged token's signature.

On the wire

alice logs in → gets an SSO token (scope: customers:all, entitlements: customers:read) → calls issue_refund → the plugin checks refunds:write against her entitlements → denied, 403, before the request reaches the MCP server or the resource API at all. bob has entitlements: customers:read customers:write refunds:write — same call succeeds, and the resource API receives a token with sub = bob, scope: refunds:write, freshly minted by the plugin sixty seconds earlier.

That's the whole machine

Identity in Keycloak, the narrowing in a custom OSS Tyk plugin, enforcement independently re-checked downstream.
